# 悬念钩子：中长期悬念与未解之谜

> **来源**：写作方法学知识库（Casting-Workflow 自有方法论层）的 hooks-suspense 方法论文档（提炼）。
> **用途**：设计贯穿多章的悬念、埋设伏笔、控制信息释放节奏时加载。

## 悬念的本质

悬念 = 读者「已知一部分、未知关键部分」的信息差。制造悬念不是藏信息，而是**给读者一个他们自己想回答的问题**，再控制回答的节奏。

## 三种悬念来源

| 类型 | 机制 | 示例 |
|---|---|---|
| 信息型 | 读者知道有秘密，不知道答案 | 那封信里写了什么？那个人的真实身份？ |
| 时间型 | 已知会发生什么，不知道何时 / 如何 | 复仇终会到来，但读者等「那一刻」 |
| 认知型 | 读者以为懂了，实则理解是错的 | 看似恩人，实为幕后黑手 |

## 悬念维持四法

1. **定期喂料**：每隔几章给一点新信息，让悬念「活着」但不立刻揭晓。
2. **伪解答**：先给一个看似合理的答案，再推翻（本身即一次小反转）。
3. **多层嵌套**：A 悬念下藏 B 悬念，揭 A 时引出 B，避免一次清空。
4. **视角错位**：用不同角色视角反复逼近同一谜底，每次只露出一角。

## 伏笔与回收

- **埋设**：伏笔要「自然到读者当时不在意」，回看才发现处处都是。
- **回收**：揭晓时让读者自己把全程重新过一遍，不靠角色大段独白解释。
- **留白**：不是所有伏笔都要回收；留白更有余味（结尾「不要所有伏笔都回收」）。

## 悬念密度自检

- [ ] 每 3–5 章至少有一个未解之谜在读者心里挂着
- [ ] 中段没有「悬念真空」（连续多章无新疑问）
- [ ] 大悬念揭晓后，是否引出新悬念（避免一次性清空）
- [ ] 伏笔的埋设是否自然、是否能在回看时被发现
- [ ] 信息释放是否符合「已知一部分、未知关键部分」的节奏

## 反模式（避免）

- 为悬疑而悬疑，谜底揭晓后毫无分量（悬念须服务人物 / 主题）。
- 用「他不知道的是」式上帝视角剧透——把悬念留給读者自己悬（见 `anti-ai/` 与 `COMMON.md`）。
- 长期挂空不收，读者遗忘或失去耐心。
